# Node File (Save nodes / Load nodes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save the node database plus the owner's annotations to a JSON file and load it back, merging without ever overwriting what the radio or the air told this session.

**Architecture:** Loaded data lives in a *third* layer inside `NodeDirectory` (`loadedNodes`, `annotations`, `loadedTelemetry`), consulted after the radio store and the air store, so a radio refresh (`markLoaded`, which replaces `nodes` wholesale) can never erase it and live data always wins. The engine coroutine owns all reads and writes (new commands, same pattern as `RequestExport`); `org.json` encoding sits in one class outside `stats/`. The Graph's candidate comparison falls back to a loaded `avg_rssi` only when a node has zero direct packets this session.

**Tech Stack:** Kotlin, Jetpack Compose, `org.json` (ships with Android), JUnit 4.

**Spec:** `docs/superpowers/specs/2026-10-24-node-file-design.md`

## Global Constraints

- `stats/` may not import `ui/` or `transport/`. File encoding lives in a new package `nodefile/`; merging lives in `NodeDirectory`.
- No new runtime dependency. JSON is `org.json`; tests need `testImplementation("org.json:json:20240303")`.
- No Russian text or comments anywhere. English code and comments; user strings in `values/strings.xml` **and** `values-es/strings.xml` (`StringsParityTest` fails otherwise).
- Zero direct packets from a node this session is the whole definition of "not enough measurements" for the `avg_rssi` fallback. No minimum count.
- Statistics (counters, relay and neighbour tables, series) are never saved and never touched by a load. Loaded averages and loaded telemetry never enter them.
- The skip list stays in `SettingsRepository`; a load unions the file's list into it, never replaces it.
- `NodeDirectory` is single-coroutine and unsynchronised on purpose: no locks.
- File format: `version` = `1`; unknown fields ignored; unknown version rejected.
- Node numbers in the file are `NodeId.format(num)` strings, parsed with `NodeId.parse`.
- Test source set runs with `unitTests.isReturnDefaultValues = true`; this hides `org.json` stub failures, so Task 1 proves the real library is in use.

## Review Focus

- A file with a different `version`, with invalid JSON, or that is empty → rejected with a message; memory unchanged.
- A file that contains a node whose `num` does not parse, or a record missing optional fields → the bad record is skipped (counted), the rest load.
- A loaded `avg_rssi` for a node that then receives its first direct packet → the live value replaces it immediately.
- Pressing Reset (statistics) after a load → loaded nodes, annotations, averages and telemetry stay; "different local node" (`clearAll`) clears them.
- Saving twice with no live data in between → the second file still carries the loaded averages.
- A radio database refresh after a load → loaded-only nodes survive; `DB(n)` still equals the radio's count.

fun annotations(nodeNum: Int): NodeAnnotations?
// existing, now layered:  node(num), identity(num), telemetry(num), locationInfo(num, from), matchingNodeNums(byte)

Layering rules (this is the whole merge):
- `loadedNodes: HashMap<Int, NodeRecord>`, `annotations: HashMap<Int, NodeAnnotations>`, `loadedTelemetry: HashMap<Int, TelemetryRecord>`.
- `applyLoaded` per entry: **annotations replaced completely** (`annotations[num] = entry.annotations`); **loaded record fill-only** (existing loaded value kept, null fields filled — reuse the `merge` convention with the *existing* argument winning); telemetry: build a `TelemetryRecord` with one sample per metric at its stored `atMillis` and `lastUptimeSeconds = uptimeSeconds`, only when no loaded telemetry exists for that node.
- Snapshot reads: `node(num)` = radio record with each null field filled from the loaded record, or the loaded record alone; `identity(num)` = air record, else radio record, else loaded record (whole-record precedence, as the storage-split design rules; source `DB` is not claimed for loaded data — add `IdentitySource.FILE` and show it nowhere yet); `telemetry(num)` = live record ?: loaded telemetry; `locationInfo` uses `node(num).dbPosition` so it falls through unchanged; `matchingNodeNums` scans nodes ∪ air ∪ loaded.
- `count` (the `DB(n)` figure) still `nodes.size`: radio only.
- `clearAll()` clears the three new maps. `clearRuntimeData()` does **not** (Reset keeps them). `markLoaded` does not touch them.

- [ ] **Step 1: Write failing tests** (`NodeDirectoryLoadTest`):
  - `a loaded node absent from memory is created` — `snapshot(emptySet()).identity(n).shortName == "ABCD"`, `matchingNodeNums` contains it, `count == 0`.
  - `radio data wins over loaded data field by field` — radio record has name, no hops; file has other name and hops 3; result: radio name, hops 3.
  - `air identity wins over loaded identity whole` — air record present; loaded identity ignored even where air field is blank.
  - `loaded annotations overwrite existing completely` — load twice with different notes and `knownAsRelay=false` the second time → second values.
  - `loaded fields fill only and never overwrite an earlier load` — second load with different long name keeps the first.
  - `a radio refresh does not remove a loaded only node` — `beginRound`, `applyNodeInfo(other)`, `markLoaded(1L)` → loaded node still present, `count == 1`.
  - `reset keeps loaded data and clearAll removes it` — `clearRuntimeData()` keeps; `clearAll()` empties.
  - `loaded telemetry is shown only until live telemetry exists` — after `applyTelemetry` the live record is returned.
  - `latchKnownRelay sets the flag and keeps notes` — annotations with notes `"x"`, latch → `knownAsRelay` true, notes `"x"`.
